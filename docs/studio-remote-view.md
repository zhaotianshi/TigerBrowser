# 远程操作窗口、输入法与中文显示

团队网页支持 Windows/Linux 客户端；浏览器仍在固定执行机运行，成员只接收画面。
本页描述原生远程模式，安装、账号初始化与网络边界见[团队服务](studio-team-service.md)。

## 独立窗口与全屏

1. 登录控制台，启动有操作权限的环境。
2. 点击“打开操作窗口”。浏览器可能要求允许本站弹出窗口；新窗口按客户端可用屏幕
   大小打开，画面占满窗口，不再嵌在管理页的小面板中。
3. 新版控制台点击“申请控制”，再点击画面操作；全屏可单独选择。旧版内置页使用
   “申请控制并全屏”。进入全屏时工具自动收起，原生标签栏、地址栏和页面
   占据显示区。一个环境同时只有一个控制者；管理员可确认接管。
4. 右侧“工具”展开浮层，可发送中文、上传文件、切换比例、释放控制或退出全屏。
   只观看时也可在工具中点击“全屏”；Esc 返回。浮层不挤占画面布局，窄屏时可滚动。
5. “关闭窗口”只关闭观看连接，不停止浏览器。连接中断可点击“重新连接”；重新打开
   默认为只读，需重新申请控制，不重放之前的输入。

在远程画面内关闭浏览器最后一个标签页则会结束该次浏览器运行。服务等待浏览器、
输入进程、私有显示及代理正常清理后，将环境标记为已停止，可再次启动。旧观看连接
随后断开不会要求人工恢复，也不会停止新启动的同一环境；真正的资源清理失败仍保留
安全屏障。此操作不删除环境、固定身份或已保存的网站数据。

默认“100% 原始大小”：一个远程像素对应一个客户端 CSS 像素，不自动缩小文字。
执行机画面大于客户端窗口时，通过画面边缘滚动条查看超出部分；浏览器自身缩放和
操作系统 DPI 仍影响最终物理像素。“适应窗口（完整画面）”则按比例缩放以完整显示，
不同宽高比可能留边，不拉伸图像。客户端窗口较小时，这两种模式不能同时保证
原始字号与完整画面。

浏览器要求用户手势才能进入真正全屏，因此弹出窗口后需点击一次“申请控制并全屏”
或“全屏”。不承诺脚本绕过该限制自动隐藏浏览器边框；权限被拒绝时会显示提示，
仍可通过操作系统最大化独立窗口。

独立窗口复用同源登录 Cookie、CSRF、观看与操作授权，地址片段只含环境 UUID，
没有密码或会话令牌，也不开放第二个桌面端口。鼠标位置根据实际图像边界映射，
包括缩放与滚动后的偏移。Linux 在启动时将原生浏览器主窗口移动并调整至既有私有
屏幕大小，再验证实际几何尺寸；不依赖窗口管理器，也不保留占用小半屏的旧窗口尺寸。
这不是修改客户端分辨率对应的指纹：私有屏幕仍来自保存的身份，客户端全屏、缩放、
最大化都不会修改它。可通过可选诊断调查实际测量差异；历史测量不作为日常启动门槛。
远程画面仅使用固定 KasmVNC 组件，经配对的 WebSocket 增量传输；不再提供 PNG 串流。
Linux 输入已改为每环境常驻 XTest 进程，普通键鼠不再逐次创建隔离进程；
释放、接管和断线仍等待原生确认，输入进程异常会停止所属环境。此项优化不改变画面帧率。
鼠标移动以首个位置立即发送、随后最多每 40 毫秒发送最新位置的方式合并，鼠标停下
时保留最后位置。Vue 使用同一输入队列，点击和按键前先发送待发移动；释放控制、
重置输入、代次变化、撤权和断线会清掉待发移动，不在重新连接后补发。

### 直接链接与新版前端

`/#remote=<环境 UUID>` 可直接打开独立页；登录后保留该片段。它引用稳定的环境 ID，
不绑定某次运行，不自动启动环境，也不包含密码或控制令牌。
开发接入使用已实现的 `GET /team/v1/profiles/{id}/remote`，读取当前运行及可用原因，
再按 `control_path` 和 `display_path` 建立配对连接。后端验证实际原生会话，不仅检查运行记录。
独立页的登录、状态与重连要求见
[API 连接契约](studio-team-api.md#71-独立操作窗口与连接信息)和
[前端连接流程](studio-team-api.md#72-前端连接与重连流程)。

## Shift、输入法与中文发送

网站打开独立的浏览器弹窗时，点击弹窗内的输入框即可把键盘输入切到该窗口。关闭弹窗后，点击原窗口继续输入。

本机输入法切换可能产生 `Process`、`Unidentified`、`Lang1`、组合事件或键码 229，
不能直接当成执行机的物理按键。网页只转发服务声明支持的物理键；输入法事件会
释放已按住的键，避免 Shift/Ctrl 卡住。后端复用原生输入校验，拒绝不支持的事件并
返回 `invalid_input`，但不关闭画面、不释放正常控制租约、不停止浏览器。真实原生
输入失败仍按原有安全边界处理，不把显示失效伪装成成功。

展开“工具”，在“中文 / 文本输入”使用 Windows/Linux 本机输入法输入后点击“发送文本”。
一次最多 1 MiB UTF-8 文本，保留换行及前后空格，超限明确拒绝，不截断。新版输入栏
支持 Enter 发送、Shift+Enter 换行，输入法选词时 Enter 不发送未完成的内容。
Linux 通过该环境私有 X11 选择显式粘贴，
Windows 通过原生 Unicode 输入；不读取或同步宿主剪贴板。直接在图像上进行完整
拼音候选输入尚未实现，发送文本不是远程安装输入法。

新版工具栏在普通窗口和全屏中均可展开；没有控制权时文本栏仍显示并提示申请控制。
“复制至本机”要求当前连接持有控制权。“选中内容”在远程浏览器内执行 Ctrl+C 后
读取新结果；“环境剪贴板”读取已复制的文本。单次最多 1 MiB，仅支持 Linux 私有
显示中的文本，不读取执行机宿主剪贴板，不自动同步。Windows 执行后端暂不支持读取。
复制过程中撤权或运行换代会拒绝返回内容。HTTPS 使用本机 Clipboard API；HTTP
使用浏览器复制命令。权限拒绝时保留文本预览和复制按钮，可按 Ctrl+C 手动复制。

环境列表提交启动时显示加载动画，“启动中”状态显示转圈；实际成功或失败通过
管理状态连接自动更新，无需刷新整个页面。进入控制台、登录恢复和离开远程路由均
重新检查状态连接；提交启动后同步读取列表。

窗口失焦或隐藏会释放控制；画面失焦进入文本栏只释放已按住的键，不清空网站数据。
如果更新后仍关闭画面，先用 Ctrl+F5 刷新，核对 `/team/v1/me` 的 `capabilities.key_codes`
是否存在，确认前端与服务均已更新；不要删除 Profile、身份或运行记录来排查。

## 中文缺字：区分控制台与远程浏览器

控制台文字使用本站随包提供的 Noto Sans SC 字体，不依赖成员电脑或 WSL 的中文字体。
远程图像中的网站文字由执行机浏览器渲染，需要与保存的字体集合匹配的内核字体资产。
因此中文缺字不能仅凭 Ubuntu/WSL 环境判断，也不能用安装完整桌面来保证修复。

已复现的制品问题：身份包含 `Noto Sans CJK SC`，但包内缺少匹配字体，使用启动器生成的
实际 Fontconfig 配置查询时匹配成了不含汉字的数学字体。2026-10-17 对官方 Linux
`152.0.4-beta.31` 原始包的大小与摘要校验及失败证据见
[当前字体门禁](studio-native-acceptance.md#已有证据与部署门禁)。
本仓库已删除浏览器和字体构建工具，不能再用旧 `scripts/fetch-fonts.py` 命令修复。
应取得与保存身份匹配、通过真实字形检查的官方内核字体制品；不要改写保存身份、
关闭字体保护、混入系统字体或添加虚构字体名称。

部署必须使用完整的匹配制品，保留旧制品以便回溯，停机后通过内核管理选择兼容版本。
当前缺字制品尚未通过该门禁。修改资产后，历史测量不再代表
当前制品，可按[原生诊断](studio-native-acceptance.md#可选诊断测量)重新测量；这不是启动许可。
系统 `fc-list` 结果不能替代浏览器专用 Fontconfig 配置的字体名称、字形和实机渲染检查。

## Ubuntu Server 不需要完整桌面

团队服务的 `team` 依赖不包含 Qt。Linux 原生远程模式为每个环境创建私有 KasmVNC 显示，
无需 GNOME、KDE、Ubuntu Desktop、WSLg 或宿主窗口管理器。仍需浏览器运行库、
KasmVNC/xauth/xdotool/bubblewrap/xclip、Fontconfig、正确字体制品和允许用户命名空间的内核。
它在虚拟显示上运行有窗口浏览器，不是改为无头执行；
固定 KasmVNC 组件提供虚拟 X11 显示，不要求物理显示器和输入设备。
新服务器应先安装浏览器所需系统运行库，再安装原生显示工具；例如在已安装项目依赖
的环境中运行：

```bash
python -m playwright install-deps firefox
sudo apt-get install xauth xdotool bubblewrap xclip fontconfig
python scripts/install-studio-kasmvnc.py --install-system-deps --prefix "$HOME/.local/share/camoufox-studio/kasmvnc-1.5.0-studio.2"
export CAMOUFOX_KASMVNC_TOOLS="$HOME/.local/share/camoufox-studio/kasmvnc-1.5.0-studio.2"
```

第一条可能请求管理员权限，安装系统库，不用普通 Firefox 替代 Camoufox 执行内核。
浏览器制品、模型和扩展仍按团队服务说明预先安装。桌面客户端 `studio` 是另一入口，
需要 Qt 与可用图形会话；Ubuntu Desktop 安装器不等同于团队服务器安装器。
当前远程后端没有 GPU 直通或远程音频/摄像头/麦克风透传；安装桌面不会自动
使隔离浏览器获得宿主设备。认证代理还需实际服务账号的原生钥匙环可用且已解锁，
不是安装桌面就能保证后台凭据读取。服务器安装见[Ubuntu 服务器安装](studio-team-service.md#ubuntu-服务器安装)。
WSL 的 systemd 服务本身不会保证发行版一直运行，测试时需保留活动的 WSL 客户端；
正式 Linux 服务器按服务管理器部署，不依赖 Windows 终端寿命。

## 开源方案与当前实现

- [KasmVNC](https://github.com/kasmtech/KasmVNC)：浏览器访问 Linux 桌面/应用的服务端与客户端，
  是当前唯一远程画面传输。需核查对应版本文档、许可证和每环境隔离，不能直接暴露共享桌面。
- [noVNC](https://novnc.com/noVNC/)：HTML/JavaScript VNC 客户端，需要 VNC 服务端以及 WebSocket
  传输，普通 TCP 服务通常还需桥接；不是仅替换一个网页组件即可获得安全的多人控制。
- [Apache Guacamole](https://guacamole.apache.org/)：浏览器访问 RDP/VNC/SSH 的网关，适合多协议
  桌面管理，但其服务组件和整桌面权限不等于本项目的逐环境授权。

KasmVNC 使用 Studio 的授权、独占控制、私有文本和文件通道。
Vue 是唯一控制台，不提供后端切换。KasmVNC 的配套解码器只处理画面，不能
通过上游输入、剪贴板或桌面尺寸请求绕过 Studio；保存身份和服务端显示尺寸保持不变。

Linux 的 X11 显示号由服务器 `-displayfd` 原子分配。libX11 可能优先使用服务器拥有的
抽象套接字，Python Xlib 使用挂载的私有文件系统套接字；不能把 `unix/` 前缀当作
强制文件系统传输的保证。固定 KasmVNC 组件修正了私有 PID 命名空间下的内部套接字
冲突，不依赖 Ubuntu 26.04 才支持的绝对 DISPLAY 路径。

安装与版本来源见 [KasmVNC 运行组件](studio-kasmvnc-runtime.md)。实际容量与性能仍按目标设备测量。

## 回归范围

客户端测试覆盖全屏进入/退出、Esc、浮层收起、原始比例切换、滚动后的坐标映射、
不支持的输入法事件和组合开始释放修饰键。
真实 Linux 浏览器回归覆盖中文发送、无效输入的 WebSocket 保持、独立窗口只读进入、
独立登录边界、原生窄窗口恢复至固定显示尺寸、100% 图像尺寸与全窗口边界断言、
关闭窗口保留浏览器、窄屏/横屏布局，以及真实 Fontconfig 字体名称与汉字
覆盖。测试方法见[服务回归](../service-tester/README.md#studio-native-regression)。
模拟输入法事件和 Linux 实机回归不等于每一种 Windows 输入法快捷键、真实专用 Windows
执行会话、两台物理电脑或完整指纹认证均已验收。
