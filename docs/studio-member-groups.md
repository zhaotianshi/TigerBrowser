# 本机成员组与批量授权

成员组已在 Studio 桌面版实现，复用现有成员登录、环境授权和浏览器引擎。
目前只在当前执行主机的工作区内生效，不提供远程控制台或跨电脑同步。
源码修改不自动更新旧便携包；需要重新打包后，旧 EXE 才包含该功能。

## 使用流程

以管理员身份打开 Studio，在“工作区 → 团队管理 → 成员组”中操作：

1. 点击“新建组”，输入唯一名称，最多 128 个字符。
2. 选择组，点击“组内成员”，勾选操作员或只读成员并保存。
3. 点击“环境授权”，按环境勾选查看、观看或操作权限并保存。
4. 成员重新登录后，列表和操作入口使用合并后的授权。

组可包含多个成员，成员也可加入多个组。管理员无需入组，也不能被加入成员组。
已停用成员可以保留组关系，但停用期间不能登录或使用任何授权。
组名称区分大小写；环境分组和标签即使同名，也不会自动授予权限。

“删除组”需要确认，只删除组关系和该组授权，不删除成员、环境、网站数据或
直接授权。删除后，原组内成员需要重新登录；来自其他组和直接授权的权限仍然生效。
“团队管理”未选择组时，编辑和删除按钮不可用，并说明需要先选择组。

## 授权规则

最终权限是直接授权与所有所属组授权的并集，再与成员角色上限取交集：

| 角色 | 最终权限上限 |
| --- | --- |
| 管理员 | 全部环境和管理操作，不依赖组授权 |
| 操作员 | 已授权环境的 `view`、`watch`、`operate` |
| 只读成员 | 已授权环境的 `view`、`watch`，不能启停或管理 |

组授权不能包含 `manage`；创建、编辑、删除环境、修改代理和身份、Cookie 传输及
成员管理仍仅限管理员。即使组里允许操作，只读成员也不会得到 `operate`。
列表与详情需要 `view`，启停需要 `operate`，这些权限不相互隐式授予。
`watch` 用于 Linux 原生远程预览的观看授权；输入和受限文件交换还要求 `operate`。

成员的“环境授权”窗口仅编辑直接授权，不显示或复制组授权。
因此取消直接授权不等于取消所有访问：如果组仍有授权，成员仍有该权限。
需要撤销时，应同时检查直接授权、所属组授权及成员状态。

## 登录撤销与并发编辑

- 修改组成员时，仅新加入或移出的成员被撤销登录；未变动成员不受影响。
- 修改组授权或删除组时，撤销组内成员的全部登录，不影响无关成员。
- 保存未变动的成员列表或权限不会增加修订号，也不会撤销登录。
- 桌面命令、弹窗保存和排队执行均重新验证登录；撤销后桌面安全关闭浏览器。
- 组成员和组授权的修改携带组修订号；旧弹窗保存返回 `revision_conflict`，
  不覆盖更新后的数据。关闭旧弹窗，在成员组窗口点击“刷新”，重新打开后编辑。

组授权的多环境保存是一个事务：任何一行无效，整批回滚。
授权窗口未展示的归档环境不会因为保存其他行而失去组授权。
解除某一组的授权不会删除同一环境的直接授权或其他组授权。

## 数据与升级

团队 schema v3 增加成员组、组成员关系和组授权表，并为组配置保存修订号。
v2 升级保留现有身份、网站数据、直接授权和有效登录，不自动创建组或授予权限。
v1 的历史修复仍会撤销旧登录；具体行为见 [成员使用说明](studio.md#team-members)。
升级前退出 Studio 和浏览器，备份整个工作区；不要用配置导出来代替完整备份。
不支持该团队 schema 的旧源码版本会拒绝打开，回退需要匹配的停机备份。

配置导出不包含组、组成员、组授权、登录或管理审计。
组创建、成员变化、授权变化和删除进入现有脱敏审计；不记录密码或网站内容。
本机操作系统账号仍是可信边界，应用登录不能隔离同一 OS 用户运行的其他程序。
