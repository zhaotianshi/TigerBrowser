# Studio 加密备份、隔离恢复与独占切换

已实现 Windows/Linux 共用的离线维护命令，以及可选的无头运行基线注册。
Windows 和 Ubuntu 24.04 x86_64 临时工作区的真实无头浏览器恢复演练通过；
这不代表原生远程画面或跨操作系统恢复已经验收。
旧端仍可操作时，更换服务器使用[停机迁移](studio-migration.md)，保留账号和数据，
以目标绑定的退役凭证接受新端运行条件；下文的直接独占切换仍仅适用于同主机无头基线。
备份本身不提供原生远程画面、在线热备或失联主机自动接管。
跨操作系统迁移需使用显式接受平台差异的迁移流程；原生测量是可选诊断，不会自动移植旧测量。

## 维护边界

先正常关闭 Studio、团队服务、浏览器和代理。备份与切换使用共同的工作区锁，
不是复制运行中的 Firefox 数据库。存在工作区锁或非停止的持久运行记录时拒绝执行，
不会根据 PID 消失、时间到期或删除锁来猜测资源已释放。有环境签出到成员电脑、
或签回提交尚未完成时，快照与迁移准备以 `checkout_active` 拒绝，因为快照会捕获过时数据；
先等待签回或由管理员强制解锁。快照不包含签出租约记录。
维护期间其他正常入口无法启动或修改该工作区；不要同时使用数据库编辑器、
文件同步工具或旧版程序。操作系统账号拥有工作区文件权限，仍是可信管理员。

命令由本机维护账号执行，不开放远程密钥读取、任意路径恢复或覆盖已有目录的 API。
配置导出仍只导出配置，不包含身份、Cookie、网站数据、成员或授权。

## 安装与密钥

在仓库根目录安装团队锁文件和本地源码：

```bash
python -m pip install -r pythonlib/team-requirements.lock
python -m pip install --no-deps -e ./pythonlib
```

为下列命令预先准备已有的工作区 `./my-team-workspace`，以及相互独立的
`../protected-keys`、`../backups`、`../restore-area` 目录。密钥目录不能位于工作区
或归档目录内部。工作区、密钥和恢复目录必须由维护账号独占访问；Linux 使用目录
0700、密钥文件 0600，Windows 必须配置限制读取者的 NTFS ACL。Windows 的文件 mode
不能代替 ACL 检查；命令不修改系统 ACL、钥匙环或磁盘加密设置。

```bash
python -m camoufox studio-backup-key --output ../protected-keys/studio.key
```

密钥是随机 16 字节，不是口令或 Token；只写入新文件，不输出到终端，不覆盖旧文件。
备份/恢复拒绝密钥与归档同目录、密钥位于工作区、链接文件、错误长度，以及 Linux
对其他用户开放的密钥权限。密钥丢失不能恢复；将其独立保存到受保护的离线密钥库，
不要放进 Git、归档包、公开共享目录或命令参数。密钥轮换通过新密钥创建新快照，
旧快照仍需原密钥；不会静默重写历史归档。

## 注册运行基线

这是显式接受当前无头运行条件，不是认证历史环境已经具有完整清单：

```bash
python -m camoufox studio-runtime-register --data-dir ./my-team-workspace --confirm-current-runtime
```

记录当前内核完整目录（含包内字体和 schema）、默认及已记录的扩展目录的内容摘要、
已校验的固定模型、Python 包版本、宿主 OS/架构/版本，以及 Windows 标准系统/用户
字体目录的摘要。执行主机标识独立保存在当前账号的 Camoufox 缓存中，不放进快照。
旧工作区不会自动补造清单；注册不生成或重置身份。再次注册是显式接受变更，
不能在恢复隔离或有未完成运行时执行。

此记录用于停机备份和迁移的制品核验，不参与日常浏览器启动，也不阻止有窗口运行。
同机独占激活仍要求已登记的无头制品匹配；内容变化即使没有修改版本号也会失败，
不会自动升级内核或换身份。需要更新备份或迁移记录时，先验证新制品的适用性，再显式注册。

范围限制：没有认证固定原生显示尺寸、GPU/驱动、Windows 非标准注册字体、动态
进程私有字体或隔离显示服务。这不是完整 M07 原生运行清单，也不保证任何跨主机
指纹迁移。缺少独立主机标识、不同账号/主机或不匹配的制品会阻止下文的同机激活；
跨服务器迁移须使用独立的来源退役与新端基线接受流程。

## 创建快照

```bash
python -m camoufox studio-backup --data-dir ./my-team-workspace --output ../backups/team.cfxbackup --key-file ../protected-keys/studio.key
```

快照包括 SQLite 一致性副本、所有已登记 Profile 的网站数据、固定身份和身份历史、
配置、成员/组/授权、审计及已存在的运行基线。排除工作区/浏览器锁、自动化发现文件、
本机初始化口令、登录 Cookie/会话、命令/运行临时记录和系统钥匙环秘密。
已完成恢复产生的 `recovery/<owner>.lock/owner.json` 是历史证据，保留在加密快照中；
它们不会变成活动工作区锁。回执必须为普通文件，结构和所有者名称须一致，不接受链接
或额外文件。旧版遗留的空 `recovering/` 目录可保留在源工作区，快照只包含回执文件。
含回执的新快照使用格式 2；新版同时读取格式 1 和 2，旧版不能读取格式 2。
团队数据库版本 4 的既有快照仍可恢复；先核对原版本、数据库与文件摘要，再在隔离副本中迁移。
凭据依赖只记录代理 ID 与必需字段；不调用秘密回读写入归档。

采用 PyCA `cryptography` 50.0.2 的
[Cobblestone-128 流式认证加密](https://cryptography.io/en/50.0.2/cobblestone/)，
不自行实现密码算法或使用内存一次性装入完整快照。归档采用不压缩 ZIP，默认数据
上限 32 GiB、文件上限 100,000、清单上限 16 MiB；拒绝压缩归档，避免压缩炸弹。
足够的源/目标磁盘空间仍需维护账号提前准备：备份会暂存数据库、归档及回读验证数据。
明文暂存只在现有受保护工作区中，目标目录中的暂存文件始终已加密。

逐文件摘要、SQLite 完整性和外键检查、再次核对来源文件、完整加密回读均成功后，
以不覆盖目标的硬链接方式原子发布；需要支持硬链接的本地 NTFS/Linux 文件系统。
异常时保留原环境，清理本次临时数据。断电留下的未知暂存目录会阻止下一次备份，
应在确认停机后人工检查，不自动删除来源目录。正常清理不是可保证的介质安全擦除；
敏感工作区和恢复区应使用受保护、适当加密的磁盘。

Firefox 的 `parent.lock`、`.parentlock` 和 `lock` 属于运行期文件，仅在已登记 Profile
的根目录排除，不读取或归档它们的符号链接目标，也不删除来源锁。Unix 的 PID 锁
可能是悬空链接；锁是否存在或 PID 是否消失都不能代替安全停机证明。锁名目录、
嵌套同名链接、其它符号链接/重解析点及数据硬链接继续明确拒绝。此规则依据
[Firefox 原生锁实现](https://github.com/mozilla-firefox/firefox/blob/main/toolkit/profile/nsProfileLock.cpp)，
不是放宽恢复归档的链接边界。

## 隔离恢复

`--destination` 必须不存在。命令不会逐文件覆盖已有环境：

```bash
python -m camoufox studio-restore --archive ../backups/team.cfxbackup --destination ../restore-area/team-restored --key-file ../protected-keys/studio.key
```

先完整认证加密流，再验证版本、文件清单、大小、摘要与数据库；拒绝路径穿越、
绝对路径、Windows 保留名/ADS、链接、重复和大小写冲突、非登记 Profile 和未知数据。
核验后的工作区原子发布为 `../restore-area/team-restored/workspace`。
恢复副本使用新的工作区 ID 和凭据命名空间，删除旧 API 密钥及其会话，撤销所有旧登录及运行能力，并持久化
启动隔离屏障。可以登录检查配置，但桌面和团队引擎都不能启动同一身份的第二副本。

若依赖代理秘密，停止服务后用本机管理员在恢复工作区重新录入原生凭据；保持其他
配置不变。不会自动复用原工作区的秘密，也不能清除密码标志来伪装恢复成功。
备份前没有注册基线的副本可检查数据，但不能通过下列切换激活。

## 独占激活

仅支持原工作区仍可访问、停机、数据未变化、同一账号/执行主机的受控切换：

```bash
python -m camoufox studio-activate-restore --source ./my-team-workspace --restored ../restore-area/team-restored/workspace --retire-source
```

同时持有两端工作区锁；校验来源 ID、配置/身份/授权与网站文件摘要、实际运行基线和
恢复端必需秘密。来源或恢复数据发生变动、来源已退役给其他副本、制品变化、秘密缺失
都会拒绝，不隐式回滚用户的新数据。只允许重新录入秘密造成的代理更新时间变化。

先持久化来源退役并撤销登录，再提交恢复端激活。原目录不删除，仍可检查，但共同
引擎永久拒绝其启动。两个事务之间故障使两端保持禁止执行，可对同一副本恢复完成
切换；已经完成的同一切换可重复确认，不能再激活第二副本。

不能访问原主机或无法证明其停止时，副本保持隔离。上述命令只支持同主机切换；
更换服务器或显式跨系统迁移使用[服务器迁移协议](studio-migration.md)。当前没有
跳过来源验证的强制参数、在线服务备份按钮或灾难恢复协调服务；不能靠删锁、
删屏障、复制主机标识或修改数据库使双份身份同时启动。

## 验证和依赖决策

测试覆盖密钥错误、篡改/截断/追加、越界路径、覆盖拒绝、异常运行、内容变化、
运行基线变化、旧登录撤销、隔离启动、独占激活、第二副本拒绝及提交故障恢复。
Windows 真实内核 152.0.4-beta.31 在临时工作区验证了持久 Cookie、localStorage、
身份保持、来源退役及资源清理；未访问真实用户数据，也未验证 Linux 原生显示。

新增直接依赖 `cryptography==50.0.2`（Apache-2.0 OR BSD-3-Clause），用于认证的
有界流式加密；锁定其跨平台依赖，普通 CLI 不要求安装这个可选 extra。
2026-10-04 查询 OSV，cryptography 50.0.2、cffi 2.1.1、pycparser 3.0 未返回已知漏洞；
这是查询当时的结果，不是永久安全保证或完整备份/灾难恢复验收。
