# Studio 部署前检查与工作区互斥

本文说明执行主机的静态前提检查，以及团队服务、维护命令和桌面客户端缓存共用的
工作区锁。平台范围见[客户端/服务器升级设计](studio-client-server.md)：远程串流只在
Linux 服务器提供，Windows、macOS 和 Linux 客户端通过签出在本机运行环境。

## 部署前检查

在即将运行服务的系统账号和 Python 环境下执行：

```bash
python -m camoufox studio-check --mode headless
python -m camoufox studio-check --mode desktop
python -m camoufox studio-check --mode remote
```

这三条是检查命令，不会启动或切换模式。`headless` 检查无头运行的静态前提，
`desktop` 额外检查本机有窗口模式的显示条件；`remote` 目前必定返回失败，明确
说明静态检查不能认证显示/GPU/字体运行清单。团队的实测与内核异常归属恢复见
[原生部署验收](studio-native-acceptance.md)。独立
[团队远程预览](studio-team-service.md)已接入 Linux 私有显示、成员鉴权及输入撤销，
检查会报告工具和固定依赖是否存在，但不会据此认证为完整生产远程就绪。

输出为 JSON，含 `protocolVersion`、`platform`、`mode`、`scope`、`checks`、
`ok` 和 `remoteReady`。每项状态是 `pass`、`warn` 或 `fail`；存在失败时退出码为 1，
只有通过或警告时为 0。参数错误使用退出码 2。`scope` 为 `static-prerequisites`，
`ok=true` 只表示本轮静态检查没有失败，`remoteReady` 目前总为 false。
JSON 的非 ASCII 字符使用转义，避免 Windows 传统代码页管道破坏结构化输出。

检查包含内核文件、已打包版本元数据及支持范围、配置 schema、默认扩展目录/清单
和固定指纹模型摘要。默认查看当前管理规则会选中的内核，但不保存选择、不清理
旧缓存、不下载。`--executable-path` 可指定实际内核文件；检查不会读取工作区设置，
所以使用自定义内核的工作区需显式传入相同路径。仅支持这里检查完整已打包内核，
未打包 Firefox 构建缺少 `version.json` 时不会被误报为可部署。

Linux `desktop` 模式缺少 `DISPLAY`/`WAYLAND_DISPLAY` 时失败；存在变量仍只给警告，
因为配置字符串不能证明显示服务器可连接。Windows 使用进程窗口站的可见标志
检查是否存在交互显示条件，检查失败或不可见时拒绝判为可用；可见同样不证明
浏览器画面正常。它不会建立显示会话、改变分辨率或切换到其他用户桌面。

需要认证代理时，可显式识别原生凭据后端：

```bash
python -m camoufox studio-check --mode headless --check-credentials
```

该选项复用原生后端白名单，不读写任何密码；后端不可用会失败。识别成功仍给
警告，因为没有证明钥匙环已解锁或原工作区秘密可读。Linux 必须在实际服务账号的
凭据会话下检查；不能用登录桌面的账号结果代替后台账号。

检查不打开工作区、取得锁、生成身份、启动子进程或进行网络探测。没有验证字体
完整性、内核二进制摘要/架构、动态库、代理出口、磁盘容量、工作区权限或真实页面
渲染，这些仍需要对应安装检查及真实浏览器验收；不能凭退出码 0 宣称生产部署完成。

## 工作区互斥与故障恢复

团队服务、维护命令和桌面客户端的每个服务器缓存都使用 `workspace.lock` 路径。
该路径原子创建为目录，其中 `owner.json` 只记录格式版本、管理进程 PID 和随机所有者
标记，不含凭据。早期版本桌面在同一路径创建的 `QLockFile` 锁文件同样会阻止新入口，
两种占用顺序都有回归测试。

锁只用于同一主机的可信本地文件系统，不是分布式锁。不支持共享盘、同步盘，
也不能防止绕过 Studio 直接用其他工具打开 Profile。不要运行两份工作区副本来
绕过互斥，尤其不能让两个浏览器同时使用同一份网站账户数据。

新入口不会因为锁很旧或 PID 消失就清除锁：管理进程退出并不能证明其浏览器和
代理也已停止。任何资源退出失败都会保留工作区屏障；同一引擎拒绝再启动环境。
普通启动错误在资源已正常清理时不会永久封锁工作区。
关闭浏览器最后一个标签页属于正常退出；仍连接的远程观看窗口等待该次清理完成，
不会因输入进程已经退出而误报残留资源。只有清理未能确认完成时才保留恢复屏障。

看到“工作区已被占用，或上次退出未完成”时，由本机管理员依次处理：

1. 确认实际工作区路径及其锁记录。PID 仅是调查线索，PID 复用后不能据此结束进程。
2. 停止仍在管理该目录的客户端或服务，核对与该工作区相关的浏览器、驱动和代理进程。
   不能按进程名称批量结束其他环境或其他用户的程序。
3. 只有确认相关进程全部停止后，才对工作区做完整停机备份，并将该路径的
   `workspace.lock` 重命名到管理员保留的恢复记录位置。不要删除 Firefox 自己的锁，
   不要在浏览器仍可能存活时强行解锁；无法确认就保持关闭并继续排查。
4. 重新打开唯一一个管理入口，核对环境数据。本机自动化接口重新生成发现凭据，
   调用方必须重新读取 `automation.json`；旧地址、Token 和租约不应复用。

上述人工流程适用于客户端缓存锁和早期版本留下的锁。`studio-team` 与可选诊断命令
使用内核边界，版本 2 锁可通过[studio-recover](studio-native-acceptance.md#显式崩溃恢复)
明确核验并恢复；不能用它追认旧锁，不会后台自动夺锁。
